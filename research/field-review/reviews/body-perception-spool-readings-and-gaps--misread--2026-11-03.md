  - Definition p.558: `The relation "happened before" denoted "→" on the set of events is the smallest relation satisfying (1) if a and b are events in the same process and a comes before b then a → b; (2) if a is the sending of a message and b is receipt of the same message then a → b; (3) if a → b and b → c then a → c.` Concurrent `a, b` iff `a ↛ b` and `b ↛ a`; `a ↛ a` so `→` is an irreflexive partial ordering.

C2: If a is the sending of a message by Pi and b is the receipt by Pj then Ci(a) < Cj(b).` "C1 means there must be a tick line between any two events on a process line, and C2 means every message line must cross a tick line."

## What is new here

The misread this angle asks about is treating physical wall-clock timestamps as if they already establish the happened-before relation — i.e., reading `Ci(a) < Cj(b)` as implying `a → b`, or reading timestamp order as total causal order, without the Lamport machinery that makes timestamps respect `→`.

1. **Clock Condition is one-directional; timestamp order does not imply causality.** Lamport's condition is `a → b ⇒ C(a) < C(b)` with the converse explicitly denied (p.559: concurrent events would otherwise have to coincide). The plant's `fresh-clock-conditional` / `break_seconds` / `window_seconds` implicitly use the converse: a smaller `epoch` is read as earlier, and `now - last_epoch` is read as time since the last event, as if `epoch` and `now` were already a common `C` satisfying the Clock Condition. They are not — they are two unsynchronised physical clocks (`Ci(t)` on phone vs host) with no `IR2` timestamp `Tm` on the spool messages and no `C1` tick guarantee on the phone side stated as an invariant, so `C(phone-epoch) < C(host-now)` does not mean the phone event happened before the host poll, nor does `epoch_a < epoch_b` imply `event_a → event_b` when epochs are non-monotone in sequence order.

2. **Partial vs total order; sequence ≠ epoch.** Lamport distinguishes the unique partial order `→` from any total extension `⇒` (p.560: different clocks yield different `⇒`). The dense queue carries two orders that already disagree: host sequence order (a Lamport-style logical tick, monotone by producer increment `IR1`-like) and phone epoch order (physical `Ci(t)`). The measured 512/2000 lagging epochs and the `max(...,0)` span clamp are the symptom: the reader publishes `window_seconds` / `break_seconds` / run spans as if epochs totally ordered the window, while the phone-side clock need not satisfy even `C1` across its own events (batching or clock step can emit `epoch` out of causal order) and delivery via spool is a message `a → b` whose receipt need not satisfy `C2: Ci(a) < Cj(b)` because no `Tm` is checked.

3. **Anomalous behavior without a drift bound.** Lamport introduces physical clocks precisely to avoid anomalous behavior where logical order differs from the user's external perception (p.561). The plant already risks that anomaly: with `FRESH_SECONDS=30.0` a live queue whose true newest phone event is 5 s old can be reported `stale` by 100 s if the final sequence row carries a lagging epoch, and conversely a stale phone can appear `fresh` if `now` and `epoch` have drifted apart — the exact anomaly Lamport warns that logical timestamps alone cannot prevent. Lamport then derives a bound on how far physical clocks can be out of synchrony as a function of drift rate `κ`, message delay `μ`, and sync interval `τ`; this plant has no such bound typed. Without a stated `|C_phone(t) - C_host(t)|` budget, `now - epoch < 30 s` has no meaning as a cross-process freshness statement.

The prior misread for this cell (2026-11-01, Rubin MCAR/MAR, discarded) is orthogonal: it asked whether dropped rows could be treated as ignorable missingness and found the plant already returns `UNKNOWN` rather than imputing. That is about loss mechanism, not about time ordering. The 2026-11-03 Li AoI recent REVISIT (freshness ≠ effectiveness, `Δ(t)` endogenous) complements this one: Li asks how stale data should drive sampling frequency; Lamport asks what "stale" even means when two clocks are involved.
