## What is new here

The spec's transfer is narrow and fits this plant's exact-SHA doctrine without borrowing philosophy:

1. **A green run is not a level.** SLSA L0→L1→L2→L3 is ordered by `provenance generation` (exists → authentic signed → unforgeable) and `isolation strength` (none → hosted → isolated), not by pass/fail. The spec's own table says L1 is "trivial to bypass". This plant's `READY` today is exactly what the spec warns L1 alone would be — provenance may exist but is not yet authenticity-gated. Naming the level in `report()` does not change the HOLD gate; it makes the current L0-with-pass visible.

2. **The GitHub Attestations bridge gives L2 on this host without a custom builder.** `actions/attest@v4` with `id-token: write, contents: read, attestations: write` emits an in-toto Statement with predicateType `https://slsa.dev/provenance/v1`, signed via Fulcio from the OIDC token and logged to Rekor (public-good instance `logged`, github-instance `not-logged`). The docs page states attestations alone provide SLSA Build L2, and L3 requires hosted+reusable workflow plus isolated guarantees. The plant already runs on GitHub Actions (`.github/workflows/ci.yml`); emitting provenance is a workflow edit, verifying it is a distribution question — both fit the spec's Producer MUSTs ("choose capable builder", "build in consistent [environment]", "distribute provenance").

3. **What to measure first, before any gate.** The spec requires provenance to "unambiguously identify" the subject by digest (`sha256:HEX` or `gitCommit:40-hex`) and to carry `buildType` + `builder.id` (transitive closure of trusted build platform). The minimal measurement for this plant's release is therefore not a new gate but a fourth field in `release_readiness.report`: `slsa_level ∈ {"L0","L1","L2","L3"} | "UNKNOWN"` derived from the existing `ci_watch.slsa_level_for` pure mapping (provenance_state + hosted + isolated + builder_id), with the attestation variant `slsa_level_for_github_attestation` when `gh attestation verify` evidence is present. A second HOLD line ("SLSA provenance unavailable — level L0") can be added later by genome, after the measurement exists; the spec's vocabulary should first be visible without widening the HOLD condition.

Critique this review keeps in view: the paper's cost argument for rerunning on flake (prior recent) is context-bound to one 1M SLoC project; this spec's L-levels are normative MUSTs for a *producer* who wants a given level, not a recommendation that every project must be L3, and L3 "usually requires significant changes". Over-claiming "we are SLSA L3" because CI passed would repeat the retired mesh's hit-count fallacy at the supply-chain layer. The test is therefore presence and verifiability of provenance, not pass/fail alone.
