## What we read

Wolfgang Mauerer, Mitchell Joblin, Damian A. Tamburri, Carlos Paradis, Rick Kazman, Sven Apel — **"In Search of Socio-Technical Congruence: A Large-Scale Longitudinal Study"**, *IEEE Transactions on Software Engineering* (MJT+21) — read full text at:

- <https://www.se.cs.uni-saarland.de/publications/docs/MJT%2B21.pdf> (PDF, 3.3 MB, fetched 200 2026-11-02, 26 pages, pdftotext 4866 lines extracted; supplementary data at <https://cdn.lfdr.de/stmc>)
- Companion quantitative critique of classic STC: 25 open-source projects (ActiveMQ…Zeppelin, Table 1), 4 data dimensions (VCS, issues, commits, eMails, Table 1), 3-month windows over up to 17 years, fully automatic codeface pipeline (<http://siemens.github.io/codeface>).

Four passages carry the metric this plant would misread if it stopped at Cataldo 2006/2008:

1. **Motif formalisation of STC as counting problem (§3.2.1, Fig. 2–3).** Two elementary socio-technical patterns in a two-mode developer–artefact graph G=(V,E): *triangle* (direct collaboration — two developers modify the same file in the window and should communicate) and *square* (indirect collaboration — two developers modify two files that depend on each other and should communicate). Each has a positive *motif* (edge present) and a negative *anti-motif* (same modification/dependency edges but communication edge missing). Counting is induced sub-graph isomorphism (injective f: V₀→V preserving missing edges, §3.2.4), not general subgraph isomorphism — decision in P, which makes the 25-project time-resolved sweep tractable. The organisational-silo effect (Fig. 2) is recovered as dominance of negative over positive motifs, not as a new primitive.

2. **Two normalised degree-of-STMC (dSTMC) metrics, r and lₐ (§4.2, Eq. 1–2).** From |M| (motif count) and |AM| (anti-motif count): signed motif percent difference `r(|AM|,|M|) = 2·(|AM|−|M|)/(|AM|+|M|) ∈ [−2,2]` (Eq. 1, averaged relative difference, scale-invariant, few discontinuous jumps) and LoC-normalised `lₐ(|AM|,|M|) = (|AM|−|M|)/|a| ∈ (−∞,∞)` (Eq. 2, |a| = lines of code, size-sensitive). Sign convention: r<0 / lₐ<0 means motifs dominate (high congruence, desirable under the hypothesis), r>0 means anti-motifs dominate; r=0 balanced. The pair deliberately separates intensive fit from extensive size — the same distinction the prior Cataldo review sought with `|CR∩CA|/|CR|` vs raw counts.

3. **Configuration-model hypothesis test for "is this motif non-random?" (§3.2.4.1, Figs. 4–6).** Before any regression, each window's empirical motif/anti-motif count c_{m,t} is compared to a discrete null distribution p_{m,t}(n)=ĉ_{m,t}/N from N rewirings of the two-mode graph preserving the exact degree sequence (maximally dissimilar Jaccard rewiring via edge switching, §3.2.4.1). One-sample t-test per (project × coupling × motif) yields p-values; ECDF over all windows (Fig. 6) rejects H₀ "counts are random" at essentially arbitrary level for both DSM/semantic and co-change couplings and both triangle/square families. Computational cost is CPU-months with distributed pipeline (§3.2.4.1 end). This is the falsification step Cataldo 2006 §5 and 2008 §5 omitted: congruence needs a null model before a threshold.

4. **Negative longitudinal result with three interpretable model families (§5–§6, Table 2).** RQ2/RQ3 test dSTMC (r and lₐ) against bug density and churn controlling for LoC, #developers, essential complexity, max nesting, etc. (Table 2 magnitudes). Stage 1: multivariate linear (+ logistic) with collinearity guard (Fig. 9); Stage 2: generalised additive models (non-parametric non-linear transforms); Stage 3: elastic net (variable selection + regularisation, fully automatic, collinearity-insensitive) over the full 25-project sample and temporal lags (forward/backward STMC↔quality). Result (Abstract, §5.1 intro, §6): *no statistical relationship in any temporal scenario*; any STMC coefficient is "orders of magnitude smaller than for other influence factors [LoC, churn, team size] and therefore not a worthwhile target for substantial optimisation" (§1 end, §5.2). Methodological control: the pipeline reproduces prior linear-model analyses for comparability and finds that earlier positive Cataldo/Herbsleb results do not replicate on this residue set with the motif operationalisation. Effect does not endure over time either — lag analysis finds no delayed impact.

**Limits the source states, kept here.** Open-source residues only (files + syntactic/co-change dependencies, mailing lists + issue trackers as communication proxies); bug density/churn are not the only quality observables — other outcomes may covary; communication edge weights and content are deliberately ignored ("frequent trivia vs. short grave discussion" §3.2.4); co-change vs DSM couplings and eMail vs issue communication give different absolute counts but same null result; degree-sequence null preserves only one graph invariant; the work is observational, not an RCT, and "significance" is reported as distribution, not single threshold (following ASA guidance [77,78], §4.1). Supplementary site carries hundreds of per-project graphs omitted from the paper.

## What this plant already does

*The plant proposes an intensive Cataldo congruence `|CR∩CA|/|CR|` as its coordination metric but has no null model, no size-separated counterpart, and no longitudinal guard — precisely the measurement step Mauerer et al. show eliminates the apparent effect.*

- **Coordination findings are categorical, not intensive, and untested against a null.** `src/mishe_tauftauf/coordination_checks.py:98` `anomalies()` emits binary findings (`stale-kernel-sync`, `missing-producer`, `dropped-producer`, `dependency-cycle`, `double-claim`, `repeated-prerequisite` :98–180) from `project()` :43 grouping of `Feed` entries. `src/mishe_tauftauf/task_state.py:22` `TaskState` carries `retry_task`/`retry_event`/`parent` and `registry()` :140, `candidates()` :294; walls (`wall.py:433` `write`, `wall.py:642` `message`) supply the channels. No denominator-normalised fit exists in the branch — the prior `coordination-and-tasks--metric--2026-10-29.md` (Cataldo CSCW 2006 + ESEM 2008) proposed pure helpers `_task_dependency_matrix`, `_coordination_requirements`, `_actual_coordination`, `congruence()` as `|CR∩CA|/|CR|` beside `anomalies()`, but that proposal is landed-review-only (genome-owned, not yet implemented), and even if landed it would inherit the critique: Cataldo's positive log(RT) regression (N=809/2,375 MRs, one product) does not survive Mauerer et al.'s 25-project motif replication.

- **Dependency and communication are named but not motif-counted.** The transfer review (`coordination-and-tasks--transfer--2026-10-29.md`, Malone) adds typed `dependency`/`depends_on` edges; `coordination_checks.py:43` groups entries by `TaskState.identity` with `bytes` and `lines()` co-occurrence available. These are the exact ingredients for the triangle (two owners on same file/task in same window) and square (owners on dependent files) motifs, yet no induced-subgraph count `|M|` / `|AM|` is taken, and no configuration-model p-value is reported. The board and dashboard therefore cannot distinguish "3 anomalies on a sparse graph" from "3 anomalies on a dense graph where chance predicts 30 motifs."

- **Volatility and temporal lag are not measured.** Cataldo Fig. 1 weekly CR churn has a direct analogue here (`Feed.entries()` slices per wake), but `anomalies()` has no windowed time series and no forward/backward lag test (Mauerer RQ3). Mauerer §1 explicitly warns that "looking for all imaginable consequences … is fundamentally impossible" and fixes on bugs/churn as residues; this plant's analogue (time task-add→task-close, wall settlement latency) is similarly available yet not regressed against any dSTMC.

- **Best nearby precedent and its limit.** `coordination-and-tasks--metric--2026-10-29.md` (same field/angle) is the paper this review critiques: it correctly adds the intensive ratio and a Jaccard volatility companion, but it treats congruence as a covariate worth maximising. Mauerer et al. §5.2–§6 show that when measured as motifs with proper null and longitudinal elastic net, the covariate's effect size is negligible compared to LoC and team size — a threshold or gate on congruence would therefore optimise noise. The follow-up `coordination-and-tasks--mechanism--2026-11-02.md` (Burrows Chubby, `wall.py` sequencer/lease) sits below the metric and does not change its interpretation.

## What is new here

**Replace a naive "higher congruence is better" gate with the motif dSTMC pair (r and lₐ) plus its configuration-model null and its longitudinal no-effect guard — a metric that tells the board when *not* to optimise coordination texture.**

1. **Triangle/square counts as the primitive, not just `CR = (A·D)·Aᵀ`.** Induced sub-graph isomorphism on the `Feed`-derived two-mode graph (owners ↔ artefacts via `TaskState`/`FeedEntry.body` modification edges, artefact↔artefact via `depends_on`/`parent`/`retry_task` plus co-change window) yields four integers per window: |M△|,|AM△|,|M□|,|AM□| (§3.2.1, Fig. 3). These are additive over `entries`, pure, and comparable across wakes — the micro-foundation that both Cataldo's CR and Herbsleb's D lack. The prior `congruence()` can be recovered as `|M|/(|M|+|AM|)` but is now accompanied by its null.

2. **r and lₐ as complementary intensive metrics (Eq. 1–2) with documented sign contract.** `r` is scale-invariant and bounded, `lₐ` leaks size so LoC effects are not hidden — together they prevent the size-confound that Table 2 diagnoses (LoC dominates bug density). Neither is a verdict; both are reported as distributions per window, exactly as Fig. 6 reports p-value ECDFs, not single thresholds.

3. **Configuration-model p-value per window as the admissibility gate.** Before any regression or alert, the board reports whether the observed |M|/|AM| would arise from a degree-preserving rewiring. A window whose motifs are compatible with the null (high p) is flagged UNKNOWN rather than low-congruence — preserving the Cataldo exclusion of |CR|=0 and extending it to random structure. This is the CPU-month check Mauerer et al. pay; this plant's analogue is cheap because its graph is tiny (owners ≤ ~dozen, files ≤ 20 analysed modules — §2/§3 census), so exact or sampled rewiring per wake is trivial.

4. **Longitudinal regression scaffold that expects a null.** Helpers are pure and return data for external regression; docstrings state the empirical prior (Mauerer Abstract + §1 end: STMC not related to bugs/churn in any temporal scenario, effect orders smaller than LoC/dev count) and therefore *forbid* a `r < −1` or `congruence > 0.7` gate. Any future `checks/congruence-report.py` or board panel must plot r/lₐ alongside bug density/churn (or task-add→close time) and report effect size relative to LoC, not a GREEN/RED threshold — exactly the "relevance, not significance" stance (§5.1, [77,78]).

Limits kept: motif choice is minimal (triangle/square only; silo/priggish smells are composites, §3.2.1); communication proxy is mailing-list/issue-comment analogue (here: `[dm]` and `signal`/`comment` entries — content weight ignored); co-change vs DSM/syntactic coupling gives different absolute counts; observational design cannot prove causation; quality residues are electable — the helpers do not claim STC never matters, only that *this* dSTMC does not explain bugs/churn and should not be thresholded as if it did.

## Application

**Add motif dSTMC helpers beside `anomalies()`/`project()` in `src/mishe_tauftauf/coordination_checks.py` — pure, additive, no verdict or threshold change, no new probe, no wire-format break. This revises the 2026-10-29 Cataldo `congruence()` proposal by adding its null model and its published negative result as a guard.**

1. **Counts and pair of metrics as pure functions over `entries` (beside `AnomalyPayloads` :20 and `anomalies()` :98).** New symbols:
   - `count_motifs(entries, *, coupling="co-change", communication="dm") -> dict` returning `{"M_tri":int,"AM_tri":int,"M_sq":int,"AM_sq":int, "window":...}` — triangle = two owners modify same `identity`/`evidence` stem in window; square = owners modify dependent artefacts (`retry_task`/`parent`/`depends_on` edge plus co-change DSM fallback). Window defaults to last K entries mirroring Mauerer Δt=3 months, scaled to wall cadence (bounded slice, no I/O beyond `entries`).
   - `dstmc_r(entries, *, coupling=..., communication=...) -> float|None` implementing Eq. 1 `r = 2*(|AM|−|M|)/(|AM|+|M|)` per motif family (triangle/square) when `|AM|+|M|>0`, else `None` (UNKNOWN, as with Cataldo `|CR|==0` exclusion). Return in [−2,2].
   - `dstmc_l(entries, *, coupling=..., communication=...) -> float|None` implementing Eq. 2 `lₐ = (|AM|−|M|)/|a|` where |a| is total LoC-equivalent for artefacts in window (lines in `wall.py` `WALL_MAX_*` analogue, or `task_state` artefact size proxy), `None` when denominator zero.
   - `dstmc_report(entries, *, history=None) -> dict|None` returning `{"r_tri":..., "r_sq":..., "l_tri":..., "l_sq":..., "|M_tri|":..., "|AM_tri|":..., "|M_sq|":..., "|AM_sq|":..., "configuration_p_tri":float|None, "configuration_p_sq":float|None, "elapsed_windows":int}` or `None` when all denominators zero. `configuration_p_*` is the configuration-model p-value stub: exact enumeration when graph is tiny (owner count < 8, artefact count < 20) via sampled degree-preserving rewiring (bounded N=200 by default, deterministic seed), else `None` with docstring noting CPU-month scale for large graphs is unnecessary here — tiny graph makes p-value trivially computable.

2. **Guard documentation that prevents threshold misuse.** Each helper's docstring cites Mauerer MJT+21 §4.2 Eq. 1–2, §3.2.4.1 null, §5–§6 negative result, and states explicitly: *do not add a `dstmc_r < −1` or `congruence > 0.7` gate; regress `dstmc_r`/`dstmc_l` against task-close time/bug density with LoC and team size as controls and report effect size — the source finds the STMC coefficient is orders smaller and temporally non-persistent*. The module docstring references both Cataldo 2006/2008 (positive result, single product) and Mauerer 2021 (negative replication, 25 projects) as the pair that defines the metric's interpretation.

3. **No new daemon, no new file, no protocol change.** Counts are read from existing `Feed`/`TaskState` edges; total order remains `publication_lock`+`sequence`. Dashboard/board callers may render `dstmc_report` as a time series alongside `anomalies()` finding count and task-close latency, reproducing Mauerer Fig. 5's windowed motif curves without changing threshold enforcement.
