## What we read

Richard D. Morey, Rink Hoekstra, Jeffrey N. Rouder, Michael D. Lee, Eric-Jan Wagenmakers, **"The fallacy of placing confidence in confidence intervals"**, *Psychonomic Bulletin & Review* 23(1), pp. 103–123 (2016), DOI 10.3758/s13423-015-0947-8.

- Publisher page (abstract): <https://link.springer.com/article/10.3758/s13423-015-0947-8>
- Full PDF, read as text via `pdftotext -layout` (1350 lines, 20 pp.): <https://link.springer.com/content/pdf/10.3758/s13423-015-0947-8.pdf> — retained at `/tmp/morey-2016.pdf` (685 KiB) and `/tmp/morey-2016.txt`.

Passages used, quoted from the PDF:

1. Definition 1 (p.104): "An X% confidence interval for a parameter θ is an interval (L, U) generated by a procedure that in repeated sampling has a X% probability of containing the true value of θ, for all possible values of θ (Neyman, 1937)."
2. The procedure/interval distinction (p.104): "A confidence procedure is a random process; a confidence interval is observed and fixed." and "It is therefore helpful to differentiate a procedure (CP) from a confidence interval: an X% confidence procedure is any procedure that generates intervals cover θ in X% of repeated samples, and a confidence interval is a specific interval generated by such a process."
3. Neyman on belief (p.106, quoting Neyman 1941 pp.133–134): "it is not suggested that we can 'conclude' that [the interval contains θ], nor that we should 'believe' that [the interval contains θ]...[we] decide to behave as if we actually knew that the true value [is in the interval]. This is done as a result of our decision and has nothing to do with 'reasoning' or 'conclusion'. The reasoning ended when the [confidence procedure was derived]."
4. Fallacy 1 — Fundamental Confidence Fallacy (p.105): "If the probability that a random interval contains the true value is X%, then the plausibility or probability that a particular observed interval contains the true value is also X%; or, alternatively, we can have X% confidence that the observed interval contains the true value." The authors call this mistake the Fundamental Confidence Fallacy because "it seems to flow naturally from the definition of the confidence interval" and note the name "confidence interval" itself encourages it.
5. Fallacy 2 — Precision fallacy (p.105): "The width of a confidence interval is a measure of precision" — the folk belief that a narrow observed interval means a more precise estimate, which the paper shows is not a property of the confidence procedure.
6. Fallacy 3 — Likelihood fallacy (p.106): "A confidence interval contains the likely or plausible values for the parameter" — the folk belief that values inside the interval are more likely than those outside, which Neyman's behavioural theory does not license.

The paper's limits, kept: its critique is of frequentist confidence theory vs its folk use. It does not provide an alternative estimator; it cautions that the three properties are "considerations outside of confidence interval theory" (p.104). Its guarantees for any bound are about the procedure's long-run error rate, not about the observed interval's post-data probability.

## What this plant already does

`src/mishe_tauftauf/verdict_coverage.py` publishes the coverage/bound vocabulary the outcome path rests on, deliberately as pure text:

- `EVIDENCE_BOUND_METHOD = "clopper-pearson-upper-tail"` with definition "the distribution-free upper confidence limit for a rate: the largest b with P(X <= k | rows, b) = delta, for X binomial over the rows sampled and k of them violating" (ll.27–33). The helper `clopper_pearson_upper(errors, rows, delta)` docstring (ll.96–107) states the limit "holds only under exchangeability between the sampled rows and the row it bounds."
- `EVIDENCE_BOUND_ASSUMPTION` (ll.36–41) publishes the assumption beside the bound: "the limit holds only if the stratum's audited rows are exchangeable with the fresh rows it bounds… the coverage pair published beside the bound says how large that audited population is."
- `EVIDENCE_BOUND_STATE_VERIFIED` (ll.87–88) is explicit that `"verified"` here "means only that a bound was computed for the stratum; it does not prove the content of any outcome in it is true (the ledger's clean-audit 'verified' is a separate word with a separate meaning)." The state `unknown` carries its own reason string.
- `coverage_pair(...)` returns `population`, `judged`, `abstained`, `coverage = judged / population`, `risk_among_judged` / `risk_over_population` plus `selection_rule` and `definition`/`scope_note` — so a reader can re-derive the published numbers without importing the producer.

What the module does not publish is the reading rule the Morey paper centres on: that the `delta = 0.05` / `0.001` confidences (`EVIDENCE_BOUND_DELTAS`, ll.93) are properties of the procedure that generated the bound, not post-data probabilities that the true violation rate lies below the observed bound, and that the width of the observed bound is not a measure of precision nor does the interval single out "likely" rates. A reader who carries the folk theory will read "95% upper limit 0.12" as "there is 95% probability the true rate is below 0.12" and will read a tighter bound as "more precise knowledge" — exactly the two fallacies the paper warns develop when the procedure/interval distinction is left unstated.

That repair is not this review's subject — it shows the misread lane does land vocabulary fixes. The confidence misreading is a separate, still-unstated vocabulary gap in the bound publisher.

## What is new here

Read against Morey et al., the Clopper–Pearson upper tail in this plant is a confidence procedure in Neyman's sense: for each stratum, the bound `b(delta)` is defined before seeing the rows as the largest rate whose binomial tail `P(X <= errors | rows, b) = delta`. After the rows are seen, one number `b` is observed. Neyman's point (quoted above) is that nothing in the theory licenses the post-data inference "we have 95% confidence the true rate is below this observed b" — that is the Fundamental Confidence Fallacy. Likewise, two strata with the same `errors/rows` but different `rows` will have different `b`; a narrower `b` does not mean the estimate is more precise in a likelihood sense (Precision fallacy), and values below `b` are not thereby "likely" (Likelihood fallacy).

Transfer to this plant, without widening the source:

1. The bound's confidence is a long-run error rate of the procedure that will have covered the true rate in `1 - delta` of samples drawn under the stated exchangeability, not a plausibility of the observed bound. The module already names the assumption; it should also name this post-data limit, so a dashboard reader cannot silently upgrade "95% confidence procedure" to "95% probability this interval covers the truth."
2. The distinction is behavioural, not epistemic. Neyman's own phrasing — "decide to behave as if we actually knew" — is the correct reading of a routing decision that acts on the bound. The plant's own `verified` wording already separates a computed bound from content truth; the FCF note is the same separation for the bound's confidence.
3. The fix is documentary, not statistical. No number changes, no new estimator. The check is whether a reader can quote the bound without committing the fallacy, not whether the bound itself moves.

Limits, stated plainly:

- Applying a statistical critique of CI folk theory to an outcome-violation bound is an analogy. The bound's `delta` is a quoted confidence, not a journal-reported CI; the risk is that a future reader or an external auditor repeats the folk reading.
- The source's alternative is not adopted here. The paper suggests "other theories of interval estimation should be used instead" when a post-data likelihood is wanted. This review does not propose a Bayesian credible interval or fiducial alternative; it proposes only that the existing confidence procedure be labelled as such.
- The module is pure and has no caller that today prints a post-data probability. The gap is therefore latent, not an active misrouting.
