## What we read

**Joe Armstrong, *Making Reliable Distributed Systems in the Presence of Software Errors* (KTH/SICS Dissertation, final version 20 Nov 2003)** — read full PDF at <https://erlang.org/download/armstrong_thesis_2003.pdf> (295 pp., 859 KB, retrieved 2026-11-02; Creator pdfTeX-0.14h) + OTP supervision principle page surveyed at <https://www.erlang.org/doc/design_principles/sup_princ.html> (redirect to /doc/system/sup_princ.html, verified 2026-11-02). The thesis is the primary source; the OTP doc is context for the implemented API the thesis designs.

Four passages carry the transferable mechanism:

1. **Workers vs supervisors — clean separation (Ch. 4.3.2 pp. 106–107, Ch. 2 p. 16–22).** "One process, the worker process, does the job. Another process, the supervisor process, observes the worker. If an error occurs in the worker, the supervisor takes actions to correct the error" (p. 106). The nice properties are enumerated: workers need not handle errors; error code is generic while worker code is specific; workers and supervisors can run on different machines given `R3/R4` (distribution + failure detection primitives, p. 27–29). This is the isomorphism thesis: "Mapping the semantics of a distributed set of communicating components onto an Erlang program is greatly simplified if we can map the concurrent structure of the problem in a 1:1 manner onto the process structure" (p. 29).

2. **Let it crash + intentional programming (Ch. 4.4 pp. 107–109, Ch. 5.3 pp. 123–128).** Errors are "when the programmer doesn't know what to do" (p. 107); the prescribed code is to crash: `asm(X) -> exit({bad_arg,asm,X})` and the compiler already injects that clause (pp. 108–109). Defensive `??????` is rejected because it hides intent. Intentional programming (p. 109) replaces overloaded `dict:lookup -> {ok,Val}|notfound` with `fetch/search/is_key` whose intent is visible. Well-behaved functions (WBFs, p. 125–127, Rules 1–4) must follow the spec, raise when it is silent, add diagnostic to the exception, and assert non-functional invariants — an exception then *means* specification failure and is the supervisor's trigger.

3. **Supervision hierarchies as SSRS trees — OR vs AND (Ch. 5.2 pp. 118–122, Figs. 5.1–5.3).** Supervisors and workers form trees: "Supervisors monitor Workers and Supervisors; Workers are instances of Behaviours; Behaviours are parameterised by Well-behaved functions" (p. 119). Each supervisor carries an SSRS (Start Stop Restart Specification) per child: how to start/stop/restart it (p. 120). Two concrete disciplines: **OR** (`one_for_one`) — "If any child dies and I am an OR supervisor restart the child that died" (p. 122); **AND** (`one_for_all`) — "If any child dies and I am an AND supervisor stop all my children and restart all my children" for dependent/co-ordinated processes (p. 122). Linear hierarchy (Fig. 5.2) chains `O/SSRS1->WBF1` etc. with rule "If my parent stops me then I stop all my children; if any child dies then I restart that child" (p. 121). Hierarchy of tasks: "Try to perform a task; if you cannot perform the task, then try to perform a simpler task" (p. 118, §5.2).

4. **Stable storage and intensity as the supervisor's memory (Ch. 2.7 pp. 29–30, OTP behaviour p. 129–131, and the OTP supervisor's `MaxR/MaxT` referenced by the doc link).** Library requirements list stable storage, device drivers, code upgrade, infrastructure (p. 29). The generic `loop(Name,F,State)` (p. 125) shows the pattern: `catch F(Query,State)` → `log_error` + `crash` reply but *loop keeps same State* — the behaviour survives the WBF failure. The implemented OTP supervisor (the thesis's application Ch. 6 pp. 129ff + OTP doc) adds intensity: "too many restarts in period T → escalate" rather than hammering. The thesis's published Erlang supervisors use this to avoid restart loops.

**Limits the source states, which this review keeps.** The thesis is a research system for telecom switches (AXD301, ~1M LOC, p. vi) where processes are cheap and isolation is by copying messages (pp. 32–34, citing Gray/Tandem, PLITS/RIG). It assumes shared-nothing BEAM processes; Mishe's processes are OS pids with filesystem state, not BEAM actors. Supervision assumes synchronous linking/monitoring primitives (pp. 27–28) that Mishe does not have; Mishe's "process group" boundary is `probe_supervisor.py`'s `prctl(PDEATHSIG)` + `start_new_session` (127 LOC), a weaker guarantee.

## What this plant already does

*One-slot durable dispatch, not a supervision tree — bounded but not hierarchical, and defensive.*

`src/mishe_tauftauf/minimal_supervisor.py` (8B6, 127 LOC) owns exactly one `Dispatch(role,wake,state,pid,detail)` persisted as an INI-style `state_path` (`MinimalSupervisor(root,role).state_path`, `:38–48`, `_read/:49`, `_write/:63` with `os.replace` tmp). `dispatch(command)` (`:80`) refuses a second dispatch while `RUNNING`, spawns via `subprocess.Popen`, `reconcile(detail)` (`:120`) writes the outcome, `revert()` (`:129`) unlinks only this trial's state. Invariant in module doc: "A started worker whose outcome is not recorded remains UNKNOWN and cannot be replayed automatically" (`:5–6`). No child list, no SSRS, no restart strategy, no intensity.

`src/mishe_tauftauf/probe_supervisor.py` (9C84, 55 LOC) is a bounded probe group: `prctl(1,SIGTERM)` parent-death signal (`:32`), `os.getppid()!=parent → 124` (`:35`), `Popen(start_new_session=True, pass_fds=…)` (`:42`), `killpg(child.pid,SIGKILL)` on timeout/cancel (`:50`). It bounds one probe's group, but is not wired as a child of `MinimalSupervisor` — two supervisors for different scopes with no parent.

`src/mishe_tauftauf/recovery_policy.py` (270 LOC, pure functions `transition`/:8, `capacity`/:58, `breaker_transition`/:109) and `src/mishe_tauftauf/native_recovery.py` (1002 LOC, `classify_attempt`, `attempt_disposition`, `fresh_attempt`) are the *other* recovery — per-wake retry classification behind `STORE_LOCK` and journal reads — unrelated to the life-support dispatch. No WBF vocabulary: the worker command is an opaque `list[str]`, its exit code is the only signal, and `reconcile(detail)` records prose.

*What that means operationally.* A transient worker that exits `1` with a partial `failure.txt` is indistinguishable from a deterministic `422`-style rejection: `MinimalSupervisor` records `detail` and stops. There is no "this child is restartable with same args" vs "this child failed its specification and must not be retried identically" — the `let-it-crash` vs "handle locally" distinction is not expressed, so every failure is treated as terminal for that dispatch. There is no `OR` (restart only this wake's worker) vs `AND` (restart wall + probe + worker together because they share a pipe) — a flapping probe cannot escalate to restarting its parent supervisor. There is no intensity gate: a worker that crashes in 2 s can be redispatched immediately by the next wake, with no `MaxR in MaxT` to tip to `reconcile`/`FATAL`.

*Neighbouring isolation already exists, without the hierarchy vocabulary.* `recovery_io.py:controller_lock`, `native_recovery.py:STORE_LOCK`, `host_containment.py:pressure` are process-group/host latches, not supervision links. The circuit-breaker landed as `breaker_transition` in this same `recovery_policy.py` (field-review 2026-10-29) proves an additive pure-function gate is the right seam.

## What is new here

**The plant has a supervisor but not a supervision *hierarchy*: no SSRS, no OR/AND strategy, no WBF/intent distinction, no intensity — the four ideas the thesis was written to package as OTP.**

Three ideas transfer directly, each with a landing line in this repository and each bounded by what the source concedes.

1. **SSRS beside Dispatch — a declarative child spec, not prose `detail`.** Armstrong's SSRS is "how to start, stop and restart the entity" (p. 120, Fig. 5.1–5.2). The MinimalSupervisor equivalent is a `ChildSpec(command, restart: one_for_one|transient|permanent, shutdown_ms, intensity)` carried beside `Dispatch` and serialised in the same `state_path`. `transient` matches the thesis's "non-normal exit is error" (p. 118): only non-zero aborts are restartable; `0` or explicit `RECONCILE` is not. `one_for_all` vs `one_for_one` maps to probe+worker sharing an `os.pipe` (AND) vs independent inference/native workers (OR). This is the SSRS the `O/A` boxes in Fig. 5.3 annotate with.

2. **OR vs AND as pure functions beside `MinimalSupervisor`, mirroring `recovery_policy.transition`.** The hierarchy rules (pp. 121–122) are two functions: `or_restart(children, failed)` → restart only `failed`; `and_restart(children, failed)` → stop all then restart all. In Mishe they are pure functions over a `supervisor_row` dict analogous to `transition`'s row: `{children: [ChildSpec], strategy: "one_for_one"|"one_for_all", restarts: [(ts, child)], intensity: (MaxR, MaxT)}`. They do not spawn; they decide, and `dispatch` executes the decision. The "if my parent stops me then I stop all my children" (p. 121) is `supervisor_stop(row)` → return stop commands for every RUNNING child.

3. **Let-it-crash + intensity, not defensive wrapping.** The `asm/1` lesson (pp. 108–109) and WBF Rules 1–4 (pp. 126–127) say: do not hide a `jump` behind a fallback value; exit with `{bad_arg,…}` and let the supervisor diagnose from the `failure.txt` traceback. For Mishe that means the worker's callback is a WBF: if `failure.txt` under the attempt dir contains a complete traceback and no effect row (`native_recovery.TRACEBACK_HEADER` + empty journal), the exit is *intentional crash* → restartable; if it handled the error (wrote a reconciled `wall outcome`), it is `RECONCILE` → not restartable. Intensity (`MaxR=3 in MaxT=60s` in OTP) then gates the restart: exceeding it does not hammer — it escalates to `reconcile(detail="supervisor_intensity")` and emits `evidence=(supervisor_row, last_child_evidence)` so the wall stays UNKNOWN with a named cause rather than silent retry.

**Limits the proposal keeps.** No BEAM, no linking, no cheap processes — the first implementation is an additive descriptor + two pure strategy functions in `minimal_supervisor.py`, behind `MISHE_SUPERVISION_TREE=0`. No cgroup or pipe topology change, no new supervisor process — the existing single-slot `MinimalSupervisor` first gains a *spec* and a *strategy*, and a tree of supervisors waits for the second cut once `one_for_one` intensity proves safe. The thesis's telecom sizing (100k processes, p. 29) does not transfer.

## Application

target: src/mishe_tauftauf/minimal_supervisor.py

**Add a supervision-tree descriptor and OR/AND strategy functions beside `MinimalSupervisor` — SSRS + one_for_one/one_for_all over an intensity window, refusing to restart beyond intensity and expressed in the plant's existing `Dispatch`/`detail` vocabulary, additive behind a flag.**

1. **Add `ChildSpec` and pure strategy functions beside `MinimalSupervisor` (`:31`) in `src/mishe_tauftauf/minimal_supervisor.py`.** No I/O, no new dependency, no signature change to `dispatch/reconcile` in the first cut:

   - `ChildSpec = {id: str, command: list[str], restart: "permanent"|"transient"|"temporary", shutdown_ms: int, kind: str}` — serialised in `state_path` alongside `dispatch`. `restart` follows WBF: `permanent` always restart, `transient` only on abnormal exit, `temporary` never.
   - `supervisor_transition(previous_row, *, event, now, strategy="one_for_one", max_r=3, max_t=60) -> row` — `event` is `{child_id, exit_code, wbf_crash: bool}` where `wbf_crash` is `native_recovery._failure_record` complete-traceback vs empty-journal test (reused, not copied). Row carries `{strategy, children: [ChildSpec], restarts: [float], checked_at, state: "RUNNING"|"RESTARTING"|"INTENSITY"}`. While `len([t for t in restarts if now - t <= max_t]) >= max_r`, return `state=INTENSITY` and do not emit a restart command — the caller writes `detail="supervisor_intensity strategy=… restarts=3/60s"` and `reconcile`.
   - `or_restart` / `and_restart` are the two arms: `one_for_one` restarts only `event.child_id`; `one_for_all` stops all RUNNING children then restarts all per SSRS order. Pure, testable, mirroring `recovery_policy.breaker_transition`.

2. **Wire as a gate *around* `dispatch` without changing its call sites.** The caller that today does `sup.dispatch(cmd)` first loads `row = load_supervisor_row(role)` and classifies the last `Dispatch` exit via the WBF predicate. If `row.state == "INTENSITY"`, the caller does not `Popen` — it reconciles with `detail` containing `supervisor_intensity` and `evidence=(row_json, last_dispatch)` so the wall/gate renders the intensity rather than hammering. If `RESTARTING`, the caller dispatches only the children the strategy selects, with `shutdown_ms` as `probe_supervisor --timeout` for pipe children.

3. **Reuse the plant's existing evidence vocabulary.** `detail` is the only new user-visible surface; it follows `native_recovery.write_blocked_state`'s `reason` and `Dispatch.detail` so broken monitoring stays UNKNOWN with a named cause. Metrics are the row itself — `strategy`, `restarts`, `checked_at`, `INTENSITY` — persisted beside `MinimalSupervisor.state_path` (e.g. `{role}-supervisor.json`) so `substrate_watch`/`initiative_watch` can log transitions and operators can trip/reset by writing `INTENSITY`/`RUNNING` (the "Operations staff should be able to trip or reset" clause from the breaker review, here for supervision).

**Acceptance (deterministic, runnable from this repository):**

- `python -m py_compile src/mishe_tauftauf/minimal_supervisor.py` and `python tools/check_parsing.py` still exit 0 — the new symbols are additive with no change to `MinimalSupervisor.dispatch/reconcile` signatures in the default path.
- With `MISHE_SUPERVISION_TREE=0`, a fixture `Dispatch(role,wake,RUNNING,pid)` that exits `0` or `1` with an empty `failure.txt` produces the same `reconcile` disposition and the same `state_path` INI as before; the supervision row stays `RUNNING` with `restarts=[]`.
- With `MISHE_SUPERVISION_TREE=1`, `strategy=one_for_one, max_r=3, max_t=60`, feeding 3 consecutive `event={child_id="worker", exit_code=1, wbf_crash=True}` spaced `10 s` records `restarts=[t1,t2,t3]` and on the 4th `supervisor_transition` 5 s later returns `state=INTENSITY` — the caller creates no `Popen` and `detail` contains `supervisor_intensity`. At `now = t1 + 61 s` the next `wbf_crash` moves to `RESTARTING` and admits one `or_restart` trial; a `wbf_crash=False` (`RECONCILE`) never increments `restarts` and never trips intensity ("Not all errors should restart").
- `strategy=one_for_all` with children `["probe","worker"]` sharing a pipe: a `worker` crash in `and_restart` returns stop commands for both `probe` and `worker` then start commands for both in SSRS order; `one_for_one` returns only `worker`.
- Existing `tests/test_minimal_supervisor*` and `tests/test_recovery*` equivalents still pass — the only observable difference is the fast `detail: supervisor_intensity` on the `INTENSITY` path versus the previous "redispatch immediately" path.

**Ownership.** `src/mishe_tauftauf/minimal_supervisor.py` is the bounded worker supervisor (`MinimalSupervisor`) consumed by life-support trials; `health` is the resolver for `failure-and-recovery / native recovery, health, supervisors, watchdogs` and for substrate `UNKNOWN` delivery gaps that hammering a crashed worker creates. The supervision-tree descriptor lives beside the host-pressure `capacity` breaker (`DEGRADED/NORMAL`) so the two supervisors share one monitoring point.

**One thing this review does not ask for.** It does not propose a BEAM, a process registry, linking/monitoring, or a multi-role supervisor tree — those are the thesis's language/OTP concerns, not the minimal descriptor. It does not change `Dispatch` wire format incompatibly. A tree of supervisors supervising supervisors waits for the next review once single-supervisor intensity proves that `RESTARTING` trials are safe.
