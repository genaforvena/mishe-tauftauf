## What this plant already does

The plant already separates durable effect outcome (`completed` vs `unknown` read back from `EffectLedger` journals) and separates reservation/`drop_reserved` from dispatched operations, so the denominator for a yield-style rate is available without mixing refusal failures — the predecessor SRE/SLI review (2026-10-31 discard) noted this. The loop's `drive_native` already threads two parallel per-turn evidence arrays — `wire_usages` (provider-reported token/cost row, `turn.wire_usage`) and `fetch_ledgers` (worker's dispatch/budget row, `turn.fetch_ledger`) — both append-only, aligned with `turns`, carried across `resume_from`, and explicitly `None` for UNKNOWN rather than synthesized zero. `token_usage.report` and `engine_usage` already aggregate OMP `stats.db` into windowed totals by provider/model/folder with TTL and cost formatting, and `engine_boundary` records model/provider for routing. There is no histogram instrument with explicit buckets, no `gen_ai.client.inference.usage.*` counter family broken down by `gen_ai.operation.name`/`gen_ai.provider.name`/`gen_ai.token.modality`, no per-operation `operation.input_tokens`/`operation.output_tokens` histogram for p95/p99/detecting outliers, and no `time_to_first_token` / `time_per_output_token` latency decomposition. The vocabulary `inference`/`effect`/`native` occurs in the sweep but occurrence is not measurement.

## What is new here

The transferable metric family is OTel GenAI's development conventions (§Inference token metrics + §Generative AI client/server metrics) as a naming and instrument discipline, not a runtime OTel import. Four instruments map directly onto gaps in this plant:

1. `gen_ai.client.operation.duration` (Histogram `s`, buckets `[0.01 … 81.92]`) and `gen_ai.server.request.duration` with required `gen_ai.operation.name` (`chat`/`generate_content`/`text_completion` etc.), `gen_ai.provider.name`, and `error.type` (Conditionally Required on error). Transfer: measure dispatch/effect handling duration per operation, retaining the plant's UNKNOWN-never-zero rule (failed turns without a terminal stay `None`, not zero; `error.type` carries the `WorkerError` class / provider error code as low-cardinality label, distinct from the effect's `unknown`/`started-without-outcome`).
2. `gen_ai.client.inference.usage.{input_tokens,output_tokens,cache_read.input_tokens,cache_write.input_tokens,reasoning.output_tokens}` (Counter `{token}`) — primary for consumption and cost proxy, broken down by `gen_ai.token.modality` (Required, plus `unknown` when modality cannot be determined), `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`/`gen_ai.response.model`. Transfer: count tokens from `wire_usages` per-turn rows (which already carry provider `usage` when available) as monotonic counters; each modality contribution is strictly positive and summed per operation, matching OTel's "SHOULD add up to the corresponding total" rule.
3. `gen_ai.client.inference.operation.{input_tokens,output_tokens}` (Histogram `{token}`) — per-operation distribution for p95/p99/outlier detection, deliberately NOT broken down by modality ("percentiles across modalities do not add up") and not for cost totals. Transfer: histogram the same per-turn `wire_usages`/`fetch_ledger` token counts, without double-counting the usage counters.
4. `gen_ai.server.time_to_first_token` (Histogram `s`, buckets `[0.001 … 10.0]`) and `gen_ai.server.time_per_output_token` (Histogram `s`, buckets `[0.01 … 2.5]`) — decode-phase performance, defined as `(request_duration - time_to_first_token)/(output_tokens-1)`. Transfer: only when streaming `turn` reports `time_to_first_token` (otherwise UNKNOWN/`None`); not a derived zero from missing data.

No compilation, OTel SDK, or exporter is imported. The gap is a naming/type discipline for the existing per-turn arrays plus an explicit bucket/attribute table so any future aggregation defaults to OTel names and does not conflate latency buckets with token counters or total usage with distribution histograms. `mask`/handler or retry policy is not changed.
