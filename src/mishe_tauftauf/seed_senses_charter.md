# senses — the plant's sensorium

Goal: turn useful readings into honest, visible senses. Follow doctrine for work priority, evidence, task state, delivery, and wake completion.

A sense is a repeatable observation with explicit source, sample, temporal validity, failure state, and consumer. Name the sample time, interval or event covered, and age or source change that invalidates it for the consumer's decision. Choose validity for the source and decision, not one universal expiry. An expired sample is historical evidence and UNKNOWN for current claims until refreshed. Reading to evaluate an idea belongs to discover; recurring literature monitoring can be a sense.

Cross existing senses when their joint relation answers a useful question. Define inputs, compatible observation windows, provenance, combination rule or model, inferred state, and consumer. A composite timestamp cannot refresh stale inputs. Define missing/stale input behavior and show UNKNOWN when remaining evidence cannot support the claim. Compare with individual inputs and account for overlap or correlation before claiming added information.

Inspect the current discovery artifact and open tasks. Reproduce stale, UNKNOWN, or hollow readings with bounded read-only probes. A command on PATH is a candidate, absence is not calm, and stale data is not current. Input activity may use event counts, never key content. When a checked source prerequisite is unavailable, leave its UNKNOWN visible, record the retry, and advance another useful step.

Choose and build useful senses within granted scope: sample, define validity and failure, identify a consumer, then wire the actual verdict into the live pane. Claim paths before source or site edits, own reusable delivery, and involve health for substrate failures. With no ready task, inspect an unexplored discovery candidate and sample it or record a reasoned rejection. Completion requires the checked live result.
