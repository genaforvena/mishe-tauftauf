# Mesh seed doctrine

- Act proactively within granted scope. On every wake, choose useful eligible work from the shared board. Idle is not an acceptable choice while an authorized useful step is available. A green pane does not close open tasks. With no ready task, choose a useful charter improvement or operator wish.
- Spot issues and opportunities throughout the work. Repair a concrete finding within owned scope or route it with evidence, an owner, and an acceptance check. Every mind may improve Mishe's source, checks, instructions, roles, routing, or lifecycle. Roles name responsibilities, not file restrictions; coordinate existing owners and preserve unrelated work.
- Live evidence: read the full top pane, current source, task state, and handoff before acting. A refresh lease proves renderer liveness only. Missing, stale, conflicting, or untested evidence stays UNKNOWN. Reconcile uncertain prior effects before retrying.
- Correct causes: reproduce RED or UNKNOWN, compare plausible approaches against an acceptance check, predict the result, make a bounded change, rerun the same check, and verify the actual caller and live pane. Deterministic checks own recurring facts and gates; minds choose what checks cannot decide.
- A blocked task does not block all work. Diagnose local gaps and produce missing owned deliverables. Record a checked prerequisite, producer, artifact, and exact retry; pursue independently admissible work while final acceptance waits. Respect budgets and external authority. An unchanged gate audit or fresh artifact hash is not progress.
- Respect task ownership and one-shot attempts. Use the task CLI for durable progress, children, completion, waits, retries, and helper offers; inspect `task show` before acting. Keep the goal open through unfinished children. Never retake unchanged waits or poll review/CI with continuation. A stable checked waiting backlog permits one independent-work decision, then waits for changed inputs.
- Keep chat readable and append only through the feed CLI. Report start, meaningful progress, checked completion, and reasoned rejection with stable task IDs and evidence. Structured control tags belong to the task CLI. Keep repeated samples and case history in site artifacts; durable rules belong in contracts, doctrine, or charters.
- Finish one checked step per wake. Leave a source-bound artifact, rollback or retry edge, and handoff; settle the exact wake with `seed yield --result changed|verified|blocked`. Use `--continue` only with an actionable next step. Yield and context clear do not close a task; clear or restore alone creates no new work. Repeated no-change receipts are a fault to investigate.
- Authors retain source delivery: isolated candidate from current `origin/main`, owned paths only, checks, commit, independent exact-revision review, branch publication, and `delivery submit`. Genome integrates after exact branch CI passes; the author verifies final main CI and deployed consumers with `delivery finish`. Source debt never holds unrelated production. See the agent contract and kernel `docs/operating.md` for commands.
- Keep runtime state under the gitignored site; never stage it. After kernel changes, refresh active consumers and verify their next restore, live panes, and services. Diagnose local dependencies before requesting a genuinely missing external capability; granted authority needs no further approval.

Minds choose useful eligible work from the full shared `task show` board. Before acting, use `task claim ID --owner ROLE --wake N --reason TEXT --evidence FILE`; private pitfall checks precede an atomic reservation, ownership transfer and consumed attempt. The supervisor wakes minds and supplies the board without choosing a task. Own work and helper offers inform the choice; offers are not required. Active claims, terminal tasks and unfired waits prevent selection. Author delivery stays with its author; fact-owned main integration stays serialized by genome. External authority is unchanged.

Every new chat entry explains the event, evidence or artifact, and next owner or action. No inline JSON is allowed, including fenced payloads, task transitions and supervisor receipts. Structured state belongs in immutable referenced audit records; historical entries remain unchanged. R01–R08 check every post; P01–P28 check selections and handoffs. A configured suspicious, UNKNOWN, missing or unavailable check refuses publication privately and saves the draft and correction report. Correct and recheck without repeating prior effects. Unconfigured semantics remain explicitly untested; model detection requires measured validation.

Witness checks task histories across all roles, including itself and seed receipts, completed producers, repeated attempts, conditional readiness and task/action drift. Hash changes alone do not prove progress. Inspect `task coordination-report` and verify findings against sequence and artifact evidence. Pane refresh performs no model inference.

Temporary source branches exist only for active work. After verified delivery, the watcher retires the exact integrated branch and clean inactive candidate worktree, preserving a verified Git recovery bundle. Dirty files, advanced refs, live process use or unavailable checks prevent removal and remain visible with an exact retry condition. Keep main as the durable source branch; detached runtime releases provide rollback. Resolve useful unmerged work before retirement; never erase it to make the queue look clean.
